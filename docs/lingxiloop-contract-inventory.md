Document exports below are current native methods. The package now grants `documents.list` and `documents.read` when the agent has the documents capability and both read exports are bound. It derives project scope from the current conversation and checks the persisted human before and after native reading. Optional native content bindings now grant create/edit and deletion approval; rename is granted with the transactional write bindings. It uses the native renameDocument repository export on the permission transaction client, not the global renameAgentDocument facade. `test:contracts` verifies the listed read/create/rename/delete structural signatures and rejects missing/any callables. The read bridge has Python/Host and denial coverage with native-shaped fixtures; native create/edit/read/delete, Yjs persistence and atomic receipts/outbox also pass the dedicated PostgreSQL content check.

`scope.userId` also supplies document attribution and ownership in agent methods. Passing the human ID merely to satisfy authorization would silently change attribution; passing only the agent ID would skip the human boundary. The package must resolve both explicitly. Native change publication failures are swallowed by `changed()`, so a method acknowledgement proves neither event delivery nor complete task satisfaction.

### Approval continuation boundary (source inspection)

`agent-os/approval-application.ts:AgentApprovalApplication.resolve` cannot be passed through as a raw domain service: its repository joins `approvals` to legacy `agent_host_actions`, reads authorization/work identity from legacy `agent_work_items`, and `enqueueApprovalResume` inserts a new row into that old queue. `supersedeApproval` also writes legacy action rows. Enabling it unchanged would retain a second runtime authority.

Move this Agent orchestration into the package while retaining domain `approvals` and native permission checks. Required replacements are: action/work lookup from namespaced durable records; exact approved argument and request-version binding; action execution with durable reconciliation; and an idempotent continuation in the namespaced queue that preserves the original request and thread. The current old resume insert does not carry thread identity. Preserve decision authorization, teacher preview freshness, TTL, conversation membership, and rejection behavior from the native implementation.

The existing application records an approved action result separately from deciding approval and enqueuing continuation. Crash tests must cover each boundary, including an executed action with a missing result record; an approval decision alone is insufficient execution evidence. This inspection does not establish implemented approval continuation or authorize use of the old queue.

### Memory boundary (plan reference revision)

Inspected `3e0a4aa8844f6ea809e7da6064ad499d9c0ad9b1:server/src/agent-os/memory-service.ts`, `memory-processor.ts` and `server/src/__integration__/agent-memory.test.ts`. These Agent modules are absent from the current reference working tree, so they cannot be assumed to be available raw service bindings. The package now owns initial memory storage, the scoped list/recall/note/verify/pin/delete path, bounded automatic prompt recall, and durable synthesis through both local and HTTP workers. Each committed source schedules one background work item that consolidates against current scoped memories, with separate proposal and verification calls and at most 12 atomic changes. Failed jobs back off for at most three attempts. Source revocation also expires dependent unprotected synthesized records. Configured semantic recall now uses durable memory_index jobs and versioned, model-specific vectors without requiring pgvector. Automatic expiry re-verification and live-model memory quality remain incomplete. The matrix below records the full required boundary, not completed integration.

| Retained operation | Reference behavior and required boundary | Evidence required for the package |
| --- | --- | --- |
| Scoped recall | `recallMemories({companyId,agentId,scopeType,scopeId,query?,limit?,conversationId?})`; scopes are `learner`, `course` and `agent_role`. Learner memory can be shared across agents; course scope uses the authorized conversation; role scope uses the agent. Scope identities must come from live authorization, not model arguments | Cross-tenant and cross-course denial, authorized cross-agent learner recall, role isolation; recall failure does not prevent answering the original request |
| Explicit note | `writeExplicitMemory({...scope,body,kind?,sourceEventId})`; preserves origin, evidence IDs, version and confidence | A source must resolve to authorized durable input; retries cannot create duplicate notes; source provenance survives reopen |
| Verification and expiry | `verifyExplicitMemory({companyId,id})` increments version; recall excludes expired memory and reference code queues expired memories for re-verification | Scoped identity and expected-version checks, expired records excluded from active recall, original source and prior versions retained; no unscoped ID-only update |
| Evidence capture | `recordMemoryEvidence({work,learnerId,userText,assistantText})` deduplicates by source/assistant event pair and schedules synthesis | Capture only committed input/output, preserve exact source references and indicate any text truncation; evidence and queue transition survive a crash |
| Synthesis | `loadMemorySynthesisBatch(work)` selects up to 12 pending evidence items for one learner; processor makes proposal and independent verification calls, with a deadline, then `applyMemorySynthesis` commits create/update/expire changes | Actual durable package work item and lease, bounded input/output, source-ID and scope validation, stale-version rejection, transactional evidence disposition and changes; verification failure never reports synthesis committed |
| Protected memory | Synthesis cannot update/expire explicit or pinned records; changes require existing expected versions, known evidence IDs, allowed scope and confidence at least 0.6 | Attempts to overwrite explicit/pinned memory, reuse foreign evidence or race a version update fail without partial writes |
| Prompt recall | Three scope layers share a bounded prompt budget; prompt source versions contain memory ID/version pairs; teacher-managed context can omit learner recall | Memory remains contextual data, never a replacement for original input or current resource facts; bounded recall preserves the live request and its revisions |

The reference implementation depends on `agent_workspace`, `agent_memory_evidence`, the old work queue, global database access and embedding configuration. Those Agent-owned storage and scheduling dependencies must move into the package; calling the old service would retain the old runtime authority. The initial schema must be updated explicitly, with no startup DDL, legacy import or second queue. Preserve semantic recall capability, but do not preserve the old requirement that a missing vector extension prevents the current user request from running.
